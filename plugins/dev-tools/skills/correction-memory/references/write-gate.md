# Write Gate — 저장 가치 판단 기준

교정이 감지되면 저장 전에 이 기준을 적용한다.
전부 저장하면 노이즈가 되어 규칙의 가치가 떨어진다.

## 저장 O

| 기준 | 예시 |
|------|------|
| 행동을 바꾸는 교정 | "npm 말고 bun 써" |
| 두 번째 같은 교정 | 같은 패턴을 다시 지적받음 |
| 도구·라이브러리 선호 | "date-fns 대신 dayjs 써" |
| 보안·안전 | "API 키 하드코딩하지 마" |
| 사고로 이어진 판단 착오 | 요청 범위 밖을 임의로 처리했다가 데이터가 틀어짐 |

## 저장 X

| 기준 | 어디로 |
|------|--------|
| 일회성 오타·단순 실수 | 그냥 고치고 끝 |
| 컨텍스트 의존적 판단 ("이번에는 A로") | 저장 안 함 — 다음엔 B일 수 있다 |
| 프로젝트 컨벤션·아키텍처 규약 | correction이 아니라 `CLAUDE.md` 본문 |
| 이미 CLAUDE.md·기존 규칙에 있음 | 새로 만들지 말고 그 파일을 고친다 |
| 취향·미관 (코드 무관) | 저장 안 함 |
| **원인을 모르는 교정** | 무엇이 문제였는지 사용자에게 먼저 묻는다 |

마지막 줄이 핵심이다. 증상만 보고 원인을 추정해 적으면 규칙은 늘어나는데 같은 사고가 다른 형태로 반복된다.

## 판단이 어려울 때

물어본다: "이 교정을 이 프로젝트의 영구 규칙으로 저장할까요?"
