## 무엇을 답하나

**해연 한 종을 손에 넣는 네 가지 길** 중 뭐가 싼지. 행은 해연 38종이고, 잔영은 등가 경로로 이 표에 들어온다.

| 길 | 뜻 |
|---|---|
| 해연 구매 | 완제품을 그냥 산다 |
| 해연 제작 | 레시피 없이 만든다 |
| 잔영×N 구매 | 같은 종류 잔영을 배수만큼 산다 |
| 잔영×N 제작 | 같은 종류 잔영을 배수만큼 만든다 |
| 가장 싼 길 | 넷 중 최저. 해연을 그냥 살 때보다 아끼는 금액을 함께 보인다 |

레시피 제작은 별도 열이고 **판정 후보가 아니다** — 레시피를 이미 가진 사람에게만 유효해서 같은 줄에 세울 수 없다.

배수는 기본 10이고 페이지에서 바꾼다. 배수가 판정을 크게 흔든다 — 실측에서 10일 때는 38종 중 36종이 "잔영 구매"지만, 11로 올리면 26종으로 줄고 제작·구매가 각각 6종으로 늘어난다.

부위별로 묶어서 보여준다 — 무기 → 투구 → 상의 → 하의 → 장갑 → 신발 → 목걸이 → 반지 순이고, 각 묶음 안에서는 아끼는 금액이 큰 순이다.

행을 펼치면 경로별 재료 수량·단가·소계·매물 수가 나온다. 원가를 지배하는 재료가 바로 보인다 — 해연의 커브드 하프ZZ는 망령의 영혼석 한 종이 재료비의 54%다.

못 세는 길은 후보에서 빠지고, 하나도 못 세면 판정하지 않는다. 짝이 되는 잔영이 없으면 잔영 두 길이 함께 빠진다.

**잔영은 만드는 것보다 사는 게 싸다.** 실측에서 잔영 1개 제작비가 시세의 두 배 안팎이고, 38종 중 "잔영 제작"이 이긴 경우는 없다. 그래도 열로 남겨 둔 이유는 시세가 뒤집힐 수 있어서다.

## 쓰는 법

```bash
python3 scripts/collect.py items      # 아이템 목록 (1회면 충분)
python3 scripts/collect.py recipes    # 레시피 — 쿼터에 걸리면 멈춘다. 다 받을 때까지 반복 실행
python3 scripts/collect.py prices     # 시세 1회
python3 scripts/serve.py 8765         # http://localhost:8765
```

시세를 주기로 갱신하려면(기본 600초):

```bash
python3 scripts/collect.py loop ~/.mabi-equipment-cost/data.db 600
```

DB 기본 경로는 `~/.mabi-equipment-cost/data.db`다. 모든 명령의 두 번째 인자로 바꿀 수 있다.

페이지 옵션은 주소로 준다.

| 주소 | 뜻 |
|---|---|
| `?echo=7` | 잔영 배수를 7로 (상단 입력칸과 같다) |
| `?recipe=0` | 레시피 제작 열 숨기기 |
| `?sort=market&desc=0` | 열 정렬. 헤더를 클릭해도 된다 — 같은 열을 다시 누르면 방향이 뒤집힌다 |

정렬 키는 `market`(해연 구매) · `craft`(해연 제작) · `recipe` · `echo_buy` · `echo_craft` · `count`(매물) · `saving`(아끼는 금액, 기본) · `margin`(만들어 팔 때 남는 돈)이다. 값이 없는 행은 방향과 무관하게 뒤로 간다.

## 가진 재료

페이지 맨 위에서 재료별 수량을 넣는다. 거래 가능한 18종이 **영혼석 · 마력석 · 그 밖의 재료**로 묶여 있고, 안 가진 재료는 0으로 시작한다. 저장을 누르기 전에 페이지가 바뀌어도 입력은 남는다(브라우저에 임시 보관하고, 되살리면 그 사실을 알린다).

넣으면 제작 칸에 **실지출**이 함께 나온다 — `19,345 실 9,695`처럼.

행을 누르면 **그 아래에 상세가 열린다**(값 칸은 한 줄로 유지된다). 경로별 재료가 **소계가 큰 순**으로 서고, 가진 재료가 있으면 `필요 / 보유 / 살 것`과 `소계 / 실 소계`가 나뉜다.

```
해연 제작 재료   필요  보유  살 것   단가     소계   실 소계      매물
망령의 영혼석     80    76      4     94    7,520      376     4,297
심해의 마력석     15     3     12    351    5,265    4,212     1,194
파동의 영혼석     90     4     86     27    2,430    2,322     3,429
합계                                     18,985    7,358
```

원가를 무엇이 지배하는지, 그중 실제로 사야 할 게 얼마인지가 같이 보인다 — 망령의 영혼석은 소계가 가장 크지만 76개를 이미 갖고 있어 실제 지출은 376원뿐이다.

두 값을 같이 두는 이유는 답해야 할 질문이 둘이라서다. "지금 지갑에서 얼마 나가나"는 실지출이고, "재료를 그냥 팔지 만들어 팔지"는 전체 시세다. **판정은 전체 시세로 한다** — 가진 재료도 팔 수 있으므로, 실지출로 판정하면 "재료가 있으니 뭐든 만드는 게 이득"이라는 틀린 결론이 나온다.

## 데이터는 언제 쌓이나

**브라우저 새로고침(F5)은 DB만 다시 읽는다.** 시세를 새로 받으려면 페이지 상단의 **새로고침 버튼**을 누르거나 수집기를 돌린다.

버튼을 누르면 수집이 백그라운드로 돌고 진행바가 받은 건수를 따라간다(실측 1,000여 건 / 2초 안팎). 총 건수는 받아 보기 전에 모르므로 직전 수집 건수를 추정치로 쓰고, 넘으면 100%에서 멈춘다. 실패하면 이유를 그 자리에 띄운다 — 조용히 원래 화면으로 돌아가지 않는다.

- `collect.py prices` — 한 번 받는다
- `collect.py loop` — 주기로 받는다(기본 600초). 이걸 띄워 둬야 자리를 비운 동안에도 이력이 쌓인다
- 기준 시각은 원본이 주는 값이라 15분 단위로 움직인다. 같은 시각은 중복 저장하지 않으므로 주기를 더 촘촘히 잡아도 이력이 부풀지 않는다
- 레시피는 한 번 받으면 끝이다. 게임 패치 전까지 바뀌지 않는다

## 데이터 출처와 제약

출처는 mabimobi.life 비공식 API 3종이다.

| 엔드포인트 | 쿼터 |
|---|---|
| `GET /d/api/v1/market/prices?limit=500&offset=N` | 없음 (실측 1,226건 / 1.7초) |
| `GET /d/api/v1/items?search=<말머리>&limit=200` | 없음 |
| `GET /d/api/v1/items/<id>` | **있음** — IP 단위 |

지켜야 할 것 셋:

- **urllib을 쓴다.** 같은 요청을 curl로 보내면 403, urllib로 보내면 200이다(실측). 외부 HTTP 라이브러리로 바꾸면 차단된다.
- **레시피는 1회만 받는다.** 상세 API에만 쿼터가 걸리고, 레시피는 게임 패치 전까지 바뀌지 않는다. 실측에서 한 번에 39종을 받고 끊겼다. `collect.py recipes`는 받은 만큼 유지하고 다음 실행에서 못 받은 것부터 잇는다 — 76종을 39 + 37로 나눠 받았다.
- **끊기면 바로 재시도하지 마라.** 429 본문이 `Expected available in N seconds`를 주지만 그 시간이 지나도 안 풀린다. 5분 간격 8회(약 40분) 재시도에서 한 건도 더 받지 못했고, 몇 시간 뒤에야 풀렸다. 끊기면 그날은 두고 나중에 `collect.py recipes`를 다시 부르는 게 빠르다.
- **게임 클라이언트 패킷은 쓰지 않는다.** 약관 위반이고, 필요한 데이터가 이미 API에 있다.

재료와 시세는 `재료.itemId` = `시세.codex_item_id`로 잇는다. 이름으로 맞추지 않는다 — 시세 1,226건에 동명 항목이 74건 있다.

**거래 불가 재료는 레시피 아이템만이 아니다.** `세공된 페리도트ZZ`가 그렇고, 페리도트 링·네크리스 4종이 여기 걸린다. 상세 응답의 재료 객체에는 거래 가능 여부가 없어서, `collect.py recipes`가 끝나면 아이템 목록 API로 이 값을 따로 채운다(쿼터 없음). 이 단계를 건너뛰면 해당 4종이 "계산 불가"로 죽는다.

## 숫자를 읽을 때

**재료비는 하한선이다.** `최저가 × 수량`이라, 실제로 80개를 사면 최저가부터 위로 훑어 올라가므로 지출은 이보다 크다. 매물 수가 필요 수량보다 적으면 해당 재료 행에 경고가 붙는다 — 그 구간에서 하한선과 실제의 격차가 가장 크다.

**레시피 제작을 일반 제작과 같은 줄에 세워 비교하지 마라.** 레시피 아이템은 거래 불가라 시세가 없다. 합계에서 빼고 라벨만 남기므로, 레시피를 이미 가진 경우에만 유효한 값이다.

**반영하지 않은 것**: 거래소 수수료·세금, 일반 제작의 대성공 확률(일반 쪽이 실제로는 조금 더 유리하다).

## 값을 못 셀 때

숨기거나 0으로 메우지 않고 상태를 그대로 보여준다.

| 화면 | 뜻 |
|---|---|
| 계산 불가 | 재료 중 시세가 없는 게 있다. 추정치로 메우지 않는다 |
| 매물 없음 | 완제품 매물이 0. 직전 가격을 현재가로 쓰지 않으므로 판정도 내지 않는다 |
| 수집 중 | 레시피를 아직 못 받았다(쿼터). 다음 주기에 채워진다 |
| — | 해당 경로가 아예 없다. 잔영의 레시피 제작 칸이 늘 이렇다 |
| 상단 노란 띠 | 시세가 임계(기본 30분)보다 낡았다. 수집기가 멈췄는지 확인할 것 |

## 잔영×11의 근거

"잔영 11개 = 해연 1개"는 커뮤니티에서 통용되는 값이고 **원 출처를 확인하지 못했다.** 부위별 마도저항 수치표도 확보하지 못해 **가격 등가만** 계산한다. 그래서 배수를 페이지 상단에서 바꿀 수 있게 두었다 — 11이 틀려도 페이지가 거짓을 말하지 않는다.

감정 옵션 수치는 API에 없다(상세 응답의 `attributes`를 실측 확인). 마도저항 계산은 수치표가 확보되면 그때 넣는다.

## 구조

계산은 `scripts/cost.py`의 `build_row` 한 곳에 모여 있다. 순수 함수라 API·저장소·렌더링과 섞이지 않는다.

```
api.py → normalize.py → store.py → report.py → serve.py
                            ↑
                        cost.py (계산)
```

테스트는 `python3 -m pytest tests/ -q`. 픽스처는 2026-08-14T16:17Z 실측 스냅샷이라 시세가 움직여도 흔들리지 않는다.
