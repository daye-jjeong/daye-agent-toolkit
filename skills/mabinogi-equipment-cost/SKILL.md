## 무엇을 답하나

**해연 한 종을 손에 넣는 네 가지 길** 중 뭐가 싼지. 행은 해연 38종이고, 잔영은 등가 경로로 이 표에 들어온다.

| 길 | 뜻 |
|---|---|
| 해연 구매 | 완제품을 그냥 산다 |
| 해연 제작 | 레시피 없이 만든다 |
| 잔영×N 구매 | 같은 종류 잔영을 배수만큼 산다 |
| 잔영×N 제작 | 같은 종류 잔영을 배수만큼 만든다 |
| 가장 싼 길 | 넷 중 최저. 해연을 그냥 살 때보다 아끼는 금액을 함께 보인다 |

레시피 제작은 별도 열이고 **판정 후보가 아니다** — 레시피를 이미 가진 사람에게만 유효해서 같은 줄에 세울 수 없다.

배수는 기본 10이고 페이지에서 바꾼다. 배수가 판정을 크게 흔든다 — 실측에서 10일 때는 38종 중 36종이 "잔영 구매"지만, 11로 올리면 26종으로 줄고 제작·구매가 각각 6종으로 늘어난다.

부위별로 묶어서 보여준다 — 무기 → 투구 → 상의 → 하의 → 장갑 → 신발 → 목걸이 → 반지 순이고, 각 묶음 안에서는 아끼는 금액이 큰 순이다.

행을 펼치면 경로별 재료 수량·단가·소계·매물 수가 나온다. 원가를 지배하는 재료가 바로 보인다 — 해연의 커브드 하프ZZ는 망령의 영혼석 한 종이 재료비의 54%다.

못 세는 길은 후보에서 빠지고, 하나도 못 세면 판정하지 않는다. **잔영은 만드는 것보다 사는 게 싸다** — 실측에서 제작비가 시세의 두 배 안팎이고 38종 중 "잔영 제작"이 이긴 경우는 없다. 그래도 열로 남긴 건 시세가 뒤집힐 수 있어서다.

## 쓰는 법

```bash
python3 scripts/collect.py items      # 아이템 목록 (1회면 충분)
python3 scripts/collect.py recipes    # 레시피 — 쿼터에 걸리면 멈춘다. 다 받을 때까지 반복 실행
python3 scripts/collect.py prices     # 시세 1회
python3 scripts/serve.py 8765         # http://localhost:8765
```

시세를 주기로 갱신하려면(기본 180초):

```bash
python3 scripts/collect.py loop ~/.mabi-equipment-cost/data.db 180
```

DB 기본 경로는 `~/.mabi-equipment-cost/data.db`다. 모든 명령의 두 번째 인자로 바꿀 수 있다.

여러 사람에게 열려면 `--public`을 붙인다. 배포 절차는 [references/deploy.md](references/deploy.md).

```bash
python3 scripts/serve.py 8765 --public
```

`--public`은 셋을 한꺼번에 바꾼다 — `0.0.0.0`에 바인딩하고, 새로고침 버튼을 끄고, 서버가 직접 3분마다 시세를 받는다. 버튼을 남겨 두면 방문자마다 원본 API를 때려 **서버 IP 하나로** 요청이 몰린다.

페이지 옵션은 주소로 준다 — `?echo=7` · `?recipe=0` · `?sort=market&desc=0`. 헤더를 클릭해도 정렬된다 → [표를 읽고 다루는 법](references/reading-the-table.md#주소로-주는-옵션)

## 가진 재료

페이지 맨 위에서 재료별 수량을 넣는다. 거래 가능한 18종이 **영혼석 · 마력석 · 그 밖의 재료**로 묶여 있고, 안 가진 재료는 0으로 시작한다. 저장을 누르기 전에 페이지가 바뀌어도 입력은 남는다(브라우저에 임시 보관하고, 되살리면 그 사실을 알린다).

재고는 서버가 아니라 **브라우저 쿠키**에 산다 — 여러 사람이 한 서버를 써도 각자의 재고를 본다. 기기를 바꾸면 다시 입력한다([왜 쿠키인지](references/architecture.md#재고가-쿠키에-사는-이유)).

넣으면 제작 칸에 **실지출**이 함께 나온다 — `19,345 실 9,695`처럼.

입력칸마다 **그 재료가 지금 얼마인지**가 붙는다.

```
망령의 영혼석  [76]   105  50 ╱╲╱▔ 139  비싼 편
특급 목재      [25]   146  ──────────  고정
```

선은 최근 14일 종가고 양 끝 숫자는 **14일 최저·최고**다. **싼 편/비싼 편은 14일 종가 백분위**로 잰다 — 값이 안 움직인 재료는 판정 대신 "고정"이라고만 한다.

**재료 이름이나 선을 누르면 그 줄 아래에 30일 차트가 펼쳐진다.** 고가~저가가 옅은 면, 종가가 선이다. 최저·최고였던 날짜와 값에 라벨이 붙고 현재가가 수평선으로 지나간다. 마우스를 올리면 그날의 시가·고가·저가·종가가 뜬다(데스크톱만).

**이 값들은 체결가가 아니라 그 순간 가장 싼 매물의 값이다.** `high 139`는 "139에 팔렸다"가 아니라 "그때는 제일 싼 것조차 139였다"는 뜻이다. 자세한 건 → [시세를 읽는 법](references/reading-the-chart.md)

폼 아래에 **내 재고 가치**가 나온다(수량 × 최저가). "만들지 말고 재료를 그냥 팔까"를 정할 때 쓴다.

일봉은 원본이 두 달치를 주므로 우리가 쌓지 않는다. 서버가 하루 한 번 받는다([주기를 어떻게 재는지](references/architecture.md#일봉-수집-주기)).

행을 누르면 그 아래 상세가 열려 경로별 `필요 / 보유 / 살 것`과 `소계 / 실 소계`가 나뉜다. **판정은 실지출이 아니라 전체 시세로 한다** — 가진 재료도 팔 수 있어서다 → [표를 읽고 다루는 법](references/reading-the-table.md)

## 데이터는 언제 쌓이나

**브라우저 새로고침(F5)은 DB만 다시 읽는다.** 시세를 새로 받으려면 상단의 **새로고침 버튼**을 누르거나 `collect.py loop`를 띄운다. `--public`에는 버튼이 없다 — 방문자마다 누르면 원본 API 요청이 서버 IP 하나로 몰려서, 대신 서버가 3분마다 받는다.

3분인 이유는 원본 기준 시각이 1·5·17·23분 간격으로 움직인 실측 때문이다. 같은 시각은 중복 저장하지 않으므로 촘촘히 받아도 이력이 부풀지 않는다. 레시피는 한 번 받으면 끝이다.

## 데이터 출처와 제약

출처는 mabimobi.life **비공식 API**다. 쿼터가 걸린 건 상세 API(`/items/<id>`) 하나뿐이고, 그건 레시피를 받을 때만 쓴다 — 배포판은 한 번도 부르지 않는다.

돌리기 전에 알아야 할 것 둘:

- **원본이 `robots.txt`로 자동 접근을 거절한다.** `User-agent: * / Disallow: /`이고 검색엔진·광고 크롤러만 허용한다. 공개로 열기 전에 [배포 문서](references/deploy.md)의 "원본 사이트의 방침"을 읽을 것
- **OpenSSL 3.x로 빌드된 파이썬으로 돌린다.** 원본이 Cloudflare 뒤에 있어 낡은 TLS 라이브러리를 막는다 — macOS 기본 `/usr/bin/python3`(LibreSSL)은 403이다. `ssl.OPENSSL_VERSION`으로 확인한다

엔드포인트 목록·쿼터 대처·이력 적재 범위 → [데이터 출처와 제약](references/api-constraints.md)

## 숫자를 읽을 때

**재료비는 하한선이다.** `최저가 × 수량`이라, 실제로 80개를 사면 최저가부터 위로 훑어 올라가므로 지출은 이보다 크다. 매물 수가 필요 수량보다 적으면 해당 재료 행에 경고가 붙는다 — 그 구간에서 하한선과 실제의 격차가 가장 크다.

**레시피 제작을 일반 제작과 같은 줄에 세워 비교하지 마라.** 레시피 아이템은 거래 불가라 시세가 없다. 합계에서 빼고 라벨만 남기므로, 레시피를 이미 가진 경우에만 유효한 값이다.

**반영하지 않은 것**: 거래소 수수료·세금, 일반 제작의 대성공 확률(일반 쪽이 실제로는 조금 더 유리하다).

## 값을 못 셀 때

숨기거나 0으로 메우지 않고 상태를 그대로 보여준다.

| 화면 | 뜻 |
|---|---|
| 계산 불가 | 재료 중 시세가 없는 게 있다. 추정치로 메우지 않는다 |
| 매물 없음 | 완제품 매물이 0. 직전 가격을 현재가로 쓰지 않으므로 판정도 내지 않는다 |
| 수집 중 | 레시피를 아직 못 받았다(쿼터). 다음 주기에 채워진다 |
| — | 해당 경로가 아예 없다. 잔영의 레시피 제작 칸이 늘 이렇다 |

상단 띠가 수집 상태를 말한다. **노란 경고는 우리 쪽이 고장났을 때만** 뜬다 — 원본이 같은 값을 계속 주는 건 경고가 아니다. 띠 네 종류와 신선도를 어떻게 재는지 → [수집 상태와 신선도](references/status-and-freshness.md)

## 잔영×11의 근거

"잔영 11개 = 해연 1개"는 커뮤니티에서 통용되는 값이고 **원 출처를 확인하지 못했다.** 부위별 마도저항 수치표도 확보하지 못해 **가격 등가만** 계산한다. 그래서 배수를 페이지 상단에서 바꿀 수 있게 두었다 — 11이 틀려도 페이지가 거짓을 말하지 않는다.

감정 옵션 수치는 API에 없다(상세 응답의 `attributes`를 실측 확인). 마도저항 계산은 수치표가 확보되면 그때 넣는다.

계산은 `scripts/cost.py`의 `build_row` 한 곳에 모여 있다. 순수 함수라 API·저장소·렌더링과 섞이지 않는다.

```
api.py → normalize.py → store.py → report.py → serve.py
                            ↑           ↑          ↑
                        cost.py    trend.py   inventory.py
                        (원가)     (추세)      (쿠키)
```
