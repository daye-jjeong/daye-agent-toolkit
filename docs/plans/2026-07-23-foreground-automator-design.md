# 마비노기 모바일 전경 전환 자동화 설계

**작성일:** 2026-07-23  
**상태:** 사용자 승인 완료  
**대상:** macOS 메뉴바 앱

## 배경

가려진 게임 창의 캡처와 최소화 감지는 실제 환경에서 동작했다. 그러나
`CGEvent.postToPid`를 사용한 동일 세션 백그라운드 클릭은 게임 동작을 한 번
전달하는 동시에 물리 포인터를 이동시키고 게임을 전면 앱으로 활성화했다.

따라서 백그라운드 입력을 가장하지 않는다. 자동화는 게임 화면을 뒤에서
관찰하되, 클릭할 때만 게임을 의도적으로 전면으로 가져온다. 클릭이 끝나면
원래 앱과 마우스 위치를 복원한다.

기존 실패 결과와 근거는
`docs/plans/2026-07-23-background-automator-design.md`에 보존한다.

## 목표

- 사용자가 필요할 때 켜고 끌 수 있는 네이티브 메뉴바 앱을 만든다.
- 가려진 게임 창을 캡처하고 현재 절차를 화면 기준으로 판별한다.
- 사용자 입력이 3초 이상 없을 때만 자동 동작한다.
- 클릭 직전에 화면과 창 신원을 다시 확인한다.
- 게임을 전면으로 가져와 클릭한 뒤 약 0.5초 후 원래 앱과 마우스 위치를
  복원한다.
- 사용자가 중간 절차를 직접 수행하면 현재 화면에 재동기화해 남은 절차부터
  이어서 처리한다.
- 가로형과 모바일 세로형 레이아웃을 자동으로 지원한다.

## 비목표와 안전 경계

- 동일 macOS 세션에서 진짜 백그라운드 입력을 제공하지 않는다.
- 최소화된 게임 창은 조작하지 않는다.
- `장면 넘기기`는 자동화하지 않는다.
- 고정 픽셀 좌표만으로 클릭하지 않는다.
- 화면 인식이 모호할 때 추측해서 클릭하지 않는다.
- 프로세스 메모리, 패킷, 비공개 API, 안티치트 우회는 사용하지 않는다.

## 전체 구조

```text
MenuBarController
        |
        v
AutomationCoordinator
        |
        +--> WindowCaptureService
        +--> SceneObserver
        +--> RuleEvaluator
        +--> UserIdleMonitor
        +--> ForegroundActionCoordinator
        +--> DiagnosticLogger
```

### WindowCaptureService

ScreenCaptureKit으로 대상 게임 창을 캡처한다. 창 ID, PID, 번들 ID, 제목,
프레임, 최소화 상태를 매 캡처마다 다시 검증한다. 창 ID가 재사용되거나
최소화되면 실패 안전 방식으로 중단한다.

### SceneObserver

Vision OCR, 색상, 간단한 도형 특성을 조합해 현재 화면과 버튼 후보를 찾는다.
버튼의 실제 텍스트 경계 상자를 반환하며 클릭 좌표는 그 중심으로 계산한다.

### RuleEvaluator

관측 결과를 JSON 규칙과 비교한다. 동일 상태가 연속 2회 관측되고 필수 텍스트,
색상, 위치 관계가 모두 맞을 때만 행동 후보를 만든다.

### UserIdleMonitor

전역 키보드·마우스 입력 시각과 세대를 추적한다. 사용자의 마지막 입력 후
3초가 지나야 행동을 허용한다. 앱이 생성한 합성 이벤트에는 식별자를 붙여
사용자 입력과 구분한다.

### ForegroundActionCoordinator

원래 전면 앱, 마우스 위치, 사용자 입력 세대, 대상 창 신원을 스냅샷으로
저장한다. 게임 활성화, 클릭, 복원 과정을 하나의 직렬 작업으로 수행한다.

## 동작 흐름

1. 가려진 게임 창을 캡처한다.
2. 화면 상태와 버튼 후보를 판별한다.
3. 동일 상태가 2회 연속 관측되면 `사용자 입력 대기` 상태로 전환한다.
4. 사용자 입력이 3초 동안 없을 때 최신 입력 세대를 저장한다.
5. 게임 창을 다시 캡처한다.
6. 창 신원, 화면 상태, 버튼 텍스트와 실제 경계 상자가 동일한지 확인한다.
7. 현재 전면 앱과 마우스 위치를 저장한다.
8. 게임을 전면으로 활성화한다.
9. 활성화 후 사용자 입력 세대가 바뀌지 않았는지 다시 확인한다.
10. 현재 버튼 경계 상자의 중심으로 마우스를 이동하고 클릭을 한 번 보낸다.
11. 약 0.5초 기다린다.
12. 원래 마우스 위치와 전면 앱을 복원한다.
13. 클릭 결과를 새 캡처로 확인하고 상태 머신을 현재 화면에 재동기화한다.

사용자 입력이 4~10단계 사이에 발생하면 클릭을 취소하고 즉시 복원한다.
10단계 이후 입력이 발생하면 추가 입력 없이 즉시 복원하고 결과 확인 단계로
넘어간다.

## 사용자의 수동 진행

내부 단계 번호보다 현재 화면을 진실의 원천으로 사용한다.

- 사용자가 `화면을 터치해 주세요`를 직접 넘기면 해당 동작을 건너뛴다.
- 사용자가 `다시 하기`를 누르면 `계속하기` 화면부터 이어간다.
- 사용자가 `계속하기`를 누르면 던전 선택 화면부터 이어간다.
- 사용자가 도전을 선택하면 선택 상태를 확인하고 `입장하기`만 처리한다.
- 사용자가 전부 진행해 던전에 입장하면 전투 상태로 재동기화하고 쿨다운한다.

알 수 없는 전환 화면에서는 클릭하지 않는다. 알려진 상태가 다시 연속 2회
관측될 때 자동화를 재개한다.

## 레이아웃과 창 크기 대응

전체 창의 정규화 좌표를 클릭점으로 사용하지 않는다. 화면 비율에 따라 먼저
레이아웃 계열을 분류한다.

- `landscape`: 기존 가로형 창
- `portrait-mobile`: 모바일 세로형 창
- `unsupported`: OCR 신뢰도나 최소 크기 조건을 충족하지 못하는 창

각 레이아웃은 OCR 검색 범위와 요소 관계만 다르게 가진다. 예를 들어 보상
화면의 행동 버튼은 가로형과 세로형 모두 화면 하단에서 찾지만, 실제 클릭은
`다시 하기` 텍스트와 버튼 배경의 현재 경계 상자 중심을 사용한다.

창 크기나 비율이 바뀌면 이전 관측, 버튼 경계 상자, 대기 중인 클릭을 모두
폐기한다. 새 크기에서 동일 상태가 2회 연속 확인된 후에만 다시 행동한다.

## 초기 화면 규칙

### CLEAR_TOUCH

- 필수 텍스트: `던전 클리어`, `화면을 터치해 주세요`
- 행동: 안전한 빈 영역 한 번 클릭
- 행동 후: 최소 2초 동안 클릭 금지
- 제외: `장면 넘기기`

### REWARD_RETRY

- 필수 텍스트: `다시 하기`
- 보조 텍스트: `나가기` 또는 `다음 구역으로`
- 행동: OCR로 찾은 `다시 하기` 버튼 중심 클릭

### CONTINUE_DIALOG

- 필수 텍스트: `던전 탐험을 계속하시겠습니까`, `계속하기`
- 행동: OCR로 찾은 `계속하기` 버튼 중심 클릭

### MISSION_SELECTION

- 필수 상태: 현재 도전 카드가 선택 가능한 상태
- 행동: 도전 카드를 한 번 클릭
- 검증: 카드가 회색 또는 비활성 선택 상태가 되고 `입장하기`가 활성화됨

### ENTER_READY

- 필수 텍스트: `입장하기`
- 필수 상태: 선택 상태 검증 완료
- 행동: OCR로 찾은 `입장하기` 버튼 중심 클릭

### RUNNING

- 전투 또는 던전 진행 화면
- 행동: 없음
- `입장하기` 성공 직후에는 약 2분 후 다시 확인한다.

## 실패 처리

- 대상 창 없음 또는 최소화: `게임 창 확인 필요`
- 접근성 또는 화면 기록 권한 없음: 권한 안내 후 중단
- OCR 신뢰도 부족: `확인 필요`, 클릭 없음
- 창 크기 또는 비율 미지원: `창 크기 확인 필요`, 클릭 없음
- 사용자 입력 재개: 대기 또는 클릭 취소
- 원래 앱 종료: 마우스 위치를 복원하고 자동화를 일시 중지
- 포커스 또는 마우스 복원 실패: 자동화를 즉시 중지하고 알림 표시
- 창 신원 변경: 현재 행동 폐기 후 새 창을 다시 탐색

같은 실패가 반복돼도 자동 클릭 빈도를 높이지 않는다. 로그와 진단 캡처만
남기고 사용자의 확인을 기다린다.

## 메뉴바 UI

- 자동화 켜기/끄기
- 현재 상태
  - 전투 대기
  - 버튼 감지
  - 사용자 입력 대기
  - 클릭 중
  - 확인 필요
- 마지막 실행 동작과 시간
- 최근 캡처 및 판정 로그 열기
- 종료

## 검증 계획

### 단위 테스트

- 가로형과 모바일 세로형 레이아웃 분류
- OCR 경계 상자에서 현재 화면 좌표로의 변환
- 창 크기 변경 시 관측과 대기 동작 무효화
- 사용자 입력 3초 유휴 게이트
- 입력 세대 변경 시 클릭 취소
- 포커스·마우스 스냅샷과 복원
- 사용자의 중간 절차 수행 후 상태 재동기화
- 알 수 없는 상태에서 행동 없음

### 실제 검증

- 가로형에서 각 절차 한 사이클
- 모바일 세로형에서 각 절차 한 사이클
- 사용자가 `다시 하기` 또는 `계속하기`를 대신 수행
- 대기 중 마우스 이동과 타이핑으로 클릭 취소
- 클릭 중 원래 앱과 마우스 위치 복원
- 동작 대기 중 창 크기와 비율 변경
- 최소화 상태에서 클릭 없음
- `장면 넘기기`가 보여도 클릭 없음

## 완료 기준

- 메뉴바에서 자동화를 켜고 끌 수 있다.
- 가로형과 모바일 세로형에서 버튼을 실제 OCR 경계 상자로 찾는다.
- 사용자가 중간 절차를 대신해도 현재 화면부터 이어간다.
- 사용자 입력 중에는 포커스를 빼앗지 않는다.
- 3초 유휴 후 실행한 클릭은 한 번만 전달된다.
- 클릭 후 원래 앱과 마우스 위치가 복원된다.
- 모호하거나 알 수 없는 화면에서는 클릭하지 않는다.
