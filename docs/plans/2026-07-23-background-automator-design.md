# Background Automator 설계

**작성일:** 2026-07-23  
**상태:** 승인된 설계  
**대상:** macOS 26, Apple Silicon  
**기술:** Swift 6, SwiftUI, ScreenCaptureKit, Vision, CoreGraphics

## 1. 문제

마비노기 모바일의 반복 던전 흐름은 여러 화면을 순서대로 확인하고 버튼을 눌러야 한다.
일반 오토클리커는 macOS의 실제 포인터와 활성 창을 공유하므로, 사용자가 다른 앱을 조작하는
동안 충돌할 수 있다. 게임 내부 버튼은 macOS 접근성 요소로 노출되지 않으므로 버튼 이름으로
직접 제어할 수도 없다.

필요한 것은 다음 조건을 만족하는 상시 실행 프로그램이다.

- 메뉴 막대에서 필요할 때 시작하고 중지한다.
- 게임 창이 다른 창 뒤에 있어도 화면 상태를 인식한다.
- 실제 마우스와 사용 중인 앱의 포커스를 가능하면 유지한다.
- 화면 상태가 정확히 일치할 때만 정해진 순서로 클릭한다.
- JSON 설정 파일로 이후 동작을 추가한다.
- 알 수 없는 화면에서는 아무것도 누르지 않는다.

## 2. 목표와 제외 범위

### 목표

- 네이티브 macOS 메뉴 막대 앱
- 특정 창 단위 캡처
- OCR과 이미지 비교를 함께 사용하는 상태 감지
- 특정 프로세스로 클릭 이벤트 전송
- 설정 파일 기반 상태 머신
- 드라이런, 로그, 즉시 중지, 오류 시 자동 일시정지
- 첫 번째 규칙으로 반복 던전 한 사이클 자동화

### 제외 범위

- 최소화된 창 지원
- 게임 프로세스 메모리 읽기 또는 수정
- 네트워크 패킷 분석
- 안티치트 우회
- `장면 넘기기` 자동 클릭
- 앱 내부에서 규칙을 시각적으로 편집하는 기능

## 3. 실제 화면 관찰 결과

2026-07-23에 Codex 컴퓨터 조작 기능으로 한 사이클을 직접 관찰했다.

1. 자동 전투가 진행된다.
2. 던전 종료 후 `던전 클리어!`와 `화면을 터치해 주세요`가 나타난다.
3. 화면 중앙 하단을 한 번 누르면 보상 연출이 시작된다.
4. 잠시 후 `나가기 / 다시 하기 / 다음 구역으로`가 있는 보상 화면이 나타난다.
5. `다시 하기`를 누르면 `던전 탐험을 계속하시겠습니까?` 확인창이 나타난다.
6. 확인창에서 `계속하기`를 누르면 던전 선택 화면으로 이동한다.
7. 선택된 도전 임무의 `선택됨`을 한 번 눌러 선택을 해제한다.
8. 선택 영역이 회색으로 바뀌고 `입장하기`가 활성화된 것을 확인한다.
9. `입장하기`를 누르면 로딩 후 자동 전투가 시작된다.

관찰한 한 판은 입장 후 결과 화면까지 약 88초가 걸렸다.

### 확인된 오클릭 위험

`장면 넘기기`는 잠깐만 나타난다. 화면을 캡처한 뒤 버튼이 사라졌는데 이전 좌표를 누르자
같은 위치의 다른 기능이 실행되어 `보유한 재화` 화면이 열렸다.

따라서 다음 원칙을 적용한다.

- `장면 넘기기`는 자동화하지 않는다.
- 좌표만으로 현재 상태를 추정하지 않는다.
- 클릭 직전에 새 프레임으로 같은 상태인지 다시 확인한다.
- 짧게 나타나는 화면은 클릭하지 않고 안정적인 다음 상태를 기다린다.

## 4. 전체 구조

```text
MenuBar UI
    │
    ├── AutomationController
    │       ├── RuleLoader
    │       ├── StateMachine
    │       └── Scheduler
    │
    ├── WindowCaptureService ── ScreenCaptureKit
    ├── Detector
    │       ├── OCRDetector ─── Vision
    │       ├── ImageDetector
    │       └── ColorDetector
    │
    ├── ClickService ────────── CoreGraphics
    └── EventLog
```

### MenuBar UI

- 자동화 시작
- 자동화 중지
- 드라이런 시작
- 현재 상태 표시
- 최근 실행 결과
- 설정 다시 불러오기
- 설정 파일 열기
- 로그 열기
- 종료

### WindowCaptureService

- 번들 ID와 창 제목으로 대상 창을 찾는다.
- ScreenCaptureKit으로 대상 창만 캡처한다.
- 다른 창 뒤에 있는 창을 지원한다.
- 대상 창이 없거나 최소화된 경우 `WAITING_FOR_APP` 상태로 전환한다.

### Detector

- OCRDetector: 한국어 문구와 해당 문구의 바운딩 박스를 반환한다.
- ImageDetector: 저장된 버튼 또는 상태 이미지를 비교한다.
- ColorDetector: 선택 해제, 버튼 활성화처럼 색상으로 구분되는 상태를 확인한다.
- 가능하면 OCR 결과의 실제 위치를 사용하고, 필요한 경우에만 상대 좌표를 사용한다.

### ClickService

- 대상 프로세스 PID에 마우스 다운/업 이벤트를 보낸다.
- 창 내부 상대 좌표를 전역 좌표로 변환한다.
- 클릭 직전 상태를 다시 캡처하고 조건이 그대로인지 확인한다.
- 실제 클릭 후 기대 상태가 나타나는지 검증한다.

### 기술 검증 게이트

Codex 컴퓨터 조작 기능에서는 다른 앱의 포커스를 유지한 채 게임 창 클릭이 성공했다.
그러나 이것이 공개 CoreGraphics API에서도 동일하게 작동한다는 증거는 아니다.

전체 앱을 구현하기 전에 작은 실험 프로그램으로 다음을 먼저 증명한다.

1. 다른 창 뒤의 게임 화면을 ScreenCaptureKit으로 캡처할 수 있다.
2. `CGEvent.postToPid`로 게임에 클릭이 전달된다.
3. 클릭할 때 실제 포인터가 움직이지 않는다.
4. 사용 중인 앱의 포커스가 유지된다.

하나라도 실패하면 전체 구현을 진행하기 전에 입력 방식을 재설계한다. 공개 API만으로
포커스 유지가 불가능하면 별도 가상 머신 또는 별도 화면 세션이 대안이다.

## 5. 첫 번째 자동화 상태 머신

```text
STOPPED
  │ 시작
  ▼
WAITING_FOR_APP
  │ 대상 창 확인
  ▼
RUNNING_COOLDOWN
  │ 60초 경과
  ▼
RUNNING_SCAN
  │ CLEAR_RESULT 감지
  ▼
CLEAR_RESULT
  │ 화면 1회 클릭
  ▼
WAIT_REWARD
  │ REWARD 감지
  ▼
REWARD
  │ 다시 하기
  ▼
CONTINUE_CONFIRM
  │ 계속하기
  ▼
DUNGEON_SELECT
  │ 선택됨 클릭
  ▼
ENTER_READY
  │ 회색 상태 + 입장 활성화 검증 후 입장하기
  └───────────────────────────────► RUNNING_COOLDOWN
```

### RUNNING_COOLDOWN

- `입장하기` 성공 후 60초 동안 캡처와 OCR을 중단한다.
- 60초 후 `RUNNING_SCAN`으로 이동한다.

### RUNNING_SCAN

- 3초마다 결과 화면을 검사한다.
- `던전 클리어!`와 `화면을 터치해 주세요`가 함께 있을 때만 다음 상태로 이동한다.

### CLEAR_RESULT

- 감지 조건을 새 프레임에서 다시 확인한다.
- `화면을 터치해 주세요` 문구 중앙 또는 지정한 안전 영역을 한 번 클릭한다.
- 클릭 후 2초 동안 아무 캡처나 클릭도 하지 않는다.
- 이후 `WAIT_REWARD`로 이동한다.

### WAIT_REWARD

- 1초마다 읽기만 한다.
- `장면 넘기기`가 보여도 누르지 않는다.
- `나가기`, `다시 하기`, `다음 구역으로`가 함께 보이면 `REWARD`로 이동한다.

### REWARD

- 세 문구가 새 프레임에도 함께 있는지 다시 확인한다.
- OCR이 반환한 `다시 하기` 문구의 중앙을 클릭한다.

### CONTINUE_CONFIRM

- 다음 문구를 모두 확인한다.
  - `던전 탐험을 계속하시겠습니까?`
  - `계속하기`
  - `나가기`
- 새 프레임에서도 같은 조합이면 `계속하기`를 클릭한다.

### DUNGEON_SELECT

- 던전 선택 화면과 `선택됨` 상태를 함께 확인한다.
- `선택됨` 영역을 한 번 클릭한다.
- 클릭 직후 바로 입장하지 않고 `ENTER_READY` 검증으로 이동한다.

### ENTER_READY

- 도전 선택 영역이 회색인지 확인한다.
- `입장하기`가 활성 색상인지 확인한다.
- 두 조건이 모두 참일 때만 `입장하기`를 클릭한다.
- 로딩 또는 전투 화면을 확인하면 `RUNNING_COOLDOWN`으로 이동한다.

## 6. 스케줄링

상태마다 검사 주기를 다르게 설정한다.

| 상태 | 주기 | 동작 |
|---|---:|---|
| STOPPED | 없음 | 아무 작업도 하지 않음 |
| WAITING_FOR_APP | 3초 | 대상 창 존재 여부만 확인 |
| RUNNING_COOLDOWN | 60초 대기 | 캡처와 OCR 중단 |
| RUNNING_SCAN | 3초 | 결과 화면 검사 |
| CLEAR_RESULT | 즉시 1회 | 상태 재검증 후 클릭 |
| WAIT_REWARD | 1초 | 보상 화면을 읽기만 함 |
| REWARD 이후 순차 상태 | 0.5초 | 다음 상태가 나타날 때까지 제한적으로 검사 |
| ERROR_PAUSED | 없음 | 사용자 재개 전까지 중지 |

각 상태는 설정 파일에서 `pollInterval`, `initialDelay`, `timeout`을 재정의할 수 있다.

## 7. 설정 파일

기본 경로:

```text
~/Library/Application Support/BackgroundAutomator/rules.json
```

이미지 템플릿 경로:

```text
~/Library/Application Support/BackgroundAutomator/templates/
```

각 규칙은 다음 개념을 표현한다.

- `app`: 번들 ID, 창 제목
- `states`: 상태 목록
- `detect`: OCR, 이미지, 색상 조건
- `match`: 모든 조건 또는 일부 조건
- `action`: 인식된 문구 클릭, 이미지 중앙 클릭, 상대 좌표 클릭
- `verifyBeforeAction`: 클릭 직전 재검증
- `afterDelay`: 클릭 후 무동작 시간
- `pollInterval`: 검사 주기
- `timeout`: 상태 제한시간
- `next`: 성공 시 다음 상태
- `onFailure`: 실패 시 정지, 대기 또는 지정 상태로 복귀

메뉴의 `설정 다시 불러오기`로 앱을 재실행하지 않고 변경 내용을 반영한다.

## 8. 오작동 방지와 오류 처리

- 문구 하나가 아니라 화면을 식별하는 문구 조합을 사용한다.
- 클릭 직전에 새 프레임으로 상태를 재검증한다.
- 각 상태에서 허용된 동작만 수행한다.
- 한 사이클에서 같은 버튼을 두 번 누르지 않는다.
- 클릭 후 예상 상태가 나오지 않으면 자동으로 일시정지한다.
- 대상 창이 사라지거나 최소화되면 대기한다.
- 설정 파일이 잘못되면 자동화를 시작하지 않는다.
- 알 수 없는 화면에서는 클릭하지 않는다.
- 메뉴 막대의 `즉시 중지`가 모든 예약 작업과 클릭을 취소한다.
- 오류 발생 시 상태, 시각, 규칙 이름, 감지 결과를 로컬 로그에 기록한다.
- 화면 이미지는 기본적으로 저장하지 않으며, 사용자가 오류 캡처를 켠 경우에만 저장한다.

## 9. 권한

- 화면 기록: 대상 창 캡처에 필요
- 손쉬운 사용: 합성 입력 전송에 필요

권한이 없으면 해당 시스템 설정 위치를 안내하고 자동화는 시작하지 않는다.

## 10. 검증

### 단위 테스트

- JSON 설정 파싱과 유효성 검사
- 상태 전이
- 시간 제한과 재시도
- 상대 좌표 변환
- OCR 조건 조합
- 이미지 및 색상 조건
- 중복 클릭 방지

### 캡처 샘플 테스트

관찰한 각 상태의 화면 샘플을 테스트 픽스처로 사용한다.

- 전투 진행 화면은 클릭하지 않는다.
- 클리어 결과 화면은 `CLEAR_RESULT`로 분류한다.
- 보상 연출은 읽기만 한다.
- 보상 선택 화면은 `REWARD`로 분류한다.
- 계속 여부 확인창은 `CONTINUE_CONFIRM`으로 분류한다.
- 선택 상태와 회색 상태를 구분한다.
- 재화 화면과 같은 예상 밖 화면은 `UNKNOWN`으로 분류하고 클릭하지 않는다.

### 드라이런

- 실제 클릭 없이 두 사이클 이상 상태 인식 순서를 기록한다.
- 상태 전이가 승인된 순서와 일치하는지 확인한다.
- 알 수 없는 화면에서 클릭 예정 동작이 생성되지 않는지 확인한다.

### 실제 통합 테스트

1. 사용자가 다른 앱을 계속 조작한다.
2. 한 사이클을 실제 클릭 모드로 실행한다.
3. 실제 포인터와 활성 앱 포커스가 유지되는지 확인한다.
4. 두 사이클 이상 반복해 상태가 정상적으로 초기화되는지 확인한다.

### 완료 기준

1. 공개 API 기술 검증 게이트를 통과한다.
2. 드라이런에서 전체 상태를 순서대로 정확히 인식한다.
3. 알 수 없는 화면에서는 클릭이 발생하지 않는다.
4. `다시 하기 → 계속하기 → 선택 해제 → 입장하기` 순서를 보장한다.
5. 클릭 후 예상 화면이 나오지 않으면 자동으로 멈춘다.
6. 실제 마우스와 사용 중인 앱의 포커스를 유지한다.
7. 대기 구간에는 캡처와 OCR을 중단한다.

## 11. 구현 위치

새 앱은 저장소의 다음 경로에 둔다.

```text
apps/background-automator/
```

Swift Package로 핵심 로직과 테스트를 분리하고, macOS 앱 타깃은 메뉴 막대 UI와 권한 처리를
담당한다. 앱 이름은 구현 계획을 확정할 때 최종 결정한다.
