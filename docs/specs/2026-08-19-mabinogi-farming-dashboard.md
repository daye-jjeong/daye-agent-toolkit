# 파밍 로그 웹 대시보드 — 어디를 돌아야 시간당 많이 먹나

> 상태: 유효

## 문제

파밍 로그는 25일치 2,500판 넘게 쌓였는데, 보려면 매번 터미널에서 분석
스크립트를 돌려야 한다. 그래서 잘 안 본다.

내용도 정작 알고 싶은 걸 못 알려준다. 지금 나오는 건 전체 기준 드랍률과
입장 방식별 드랍률이다. 실제로 판단하고 싶은 건 **"이 아이템을 시간당 가장
많이 먹으려면 어디를 어떻게 들어가 돌아야 하나"**인데, 던전별로 갈린 표가
없어서 답이 안 나온다.

특히 은동전을 쓰는 판과 안 쓰는 판은 전리품 양이 다르다(전리품 칸 수
중앙값이 무료 4칸, 재화 입장 11칸). 둘을 섞은 확률은 어느 쪽으로도 못 쓴다.

## 해결

브라우저로 열어 두고 새로고침만 하면 최신 집계가 보인다.

아이템을 고르면 **던전 × 입장 방식별로 시간당 몇 개를 먹는지** 순위로
나온다. 은동전을 쓸 때와 안 쓸 때가 갈려 있어, 지금 자기 상황에 맞는 줄만
보면 된다. 날짜별로 얼마나 돌렸는지도 같은 페이지에 있다.

## 전리품이 기록되는 경로 — 지금은 하나, 곧 둘

이 대시보드는 automator가 남기는 **화면 인식(OCR) 사이클 로그**를 읽는다.
이게 현재 유일한 소스다.

별개로, 던전 결과를 **게임 패킷에서 읽어 정확한 전리품 로그로 남기는 작업**이
딜미터기 세션에서 진행된다. 이유는 더블 루팅 전리품이 결과창 스크롤 아래
섹션에 있어 OCR로는 안 잡히기 때문이다(범위 밖 참조).

**대시보드는 소스에 종속되지 않게 만든다.** 지금은 OCR 로그를 읽되, 두 로그의
집계 단위(던전·시각·아이템·수량·입장 방식)를 같은 모양으로 맞춰, 나중에 패킷
로그가 준비되면 소스만 갈아끼우거나 두 소스를 합칠 수 있게 한다.

## 확정된 결정

| 결정 | 선택 | 왜 |
|---|---|---|
| 데이터 소스 | OCR 사이클 로그. 읽기만 한다 | 현재 유일한 소스다. 기존 스크립트엔 로그를 덮어쓰는 기능이 있는데 대시보드는 그 경로를 안 탄다 |
| 갱신 방식 | 로컬 웹서버. 새로고침할 때마다 로그를 다시 읽는다 | 로그가 지금도 계속 쌓인다. 굽어 놓은 파일은 열자마자 낡는다 |
| 집계 코드 | 기존 분석 스크립트에 얹는다. 새로 짜지 않는다 | 같은 규칙이 두 벌 생기면 터미널과 웹의 숫자가 갈린다 |
| 진입점 | 레포에서 명령 하나. 서버가 뜨고 브라우저가 열린다 | 메뉴바 앱에 넣으려면 Swift 수정·재빌드가 필요해 범위가 두 배가 된다 |
| 주 축 | 아이템을 고르면 던전 × 입장 방식 순위 | 실제 판단이 "이거 어디서 캐지"다. 던전은 이미 정해 놓고 돈다 |
| 주 지표 | 시간당 획득 개수 | "어디가 효율적인가"가 목적이다. 판당 확률은 판 소요가 다르면 비교가 안 된다 |
| 개수 세는 법 | 수량 뱃지가 있으면 그 값, 없으면 1개 | 화면 확인: 영혼석은 1개일 때 뱃지가 없고, 2개(더블 루팅)면 한 칸에 뱃지 2가 붙는다. 갱신권도 같다 |
| 판당 소요 | 연속한 판의 기록 시각 간격. 5분 넘는 간격은 제외 | 순수 전투 시간은 입장·이동·결과창을 빼먹어 실제와 5배 어긋난다. 5분 초과는 자리 비움이다 |
| 입장 방식 판정 | 기록이 있으면 그것. 없으면 전리품 칸 수로 메운다 | 기록이 약 천 판에 없다. 칸 수 판별력이 높다(무료 판 중 15칸 이상은 극소수) |
| 판정 구간 | 15칸 이상=재화, 6칸 이하=무료, 7~14칸=판정 불가 | 양 끝은 깨끗하고 가운데만 섞인다. 3구간으로 자르면 회색지대가 격리된다 |
| 추정 표시 | 칸 수로 메운 칸은 화면에서 구분한다 | 기록이 고쳐지면 추정을 걷어낼 수 있어야 한다 |
| OCR 교정 | 관대하게 매칭한다. 못 읽은 문자열은 건수를 화면에 띄운다 | 분자가 새는지가 숫자만큼 중요하다. 배지가 0에 가까우면 표를 믿는다 |
| 교정 사전 | 코드 밖 편집 가능한 파일 | 미인식 배지를 보고 한 줄 고쳐 새로고침하는 사이클이 닫혀야 한다 |
| 날짜 경계 | 한국 시각 자정 | 자정 넘겨 돌린 판이 전체의 2%도 안 된다. 6시 경계로 바꿔도 결과가 거의 안 움직인다 |
| 상태 표시 | 마지막 기록 시각·총 판수·미인식 건수를 항상 띄운다 | 앱이 멈춰도 페이지는 어제 숫자를 멀쩡히 보여준다. 0판과 오류도 달라 보여야 한다 |
| 데이터 경계선 | 집계에 쓴 기간의 시작을 화면에 적는다 | 전리품 소스가 OCR에서 패킷으로 바뀌면 수치가 달라진다. 게임 패치로 오해하면 안 된다 |

## 아이템으로 세지 않는 것

결과 화면에 뜨지만 획득물이 아닌 것들. 교정 사전에 제외로 등록한다.

- 버닝 위크 / 초심자 동행 — 이벤트·버프 표시
- 비상 탈출! 로 시작하는 문자열 — 버튼 텍스트
- 던전 탐험을 계속하시겠습니까 로 시작하는 문구 — 다이얼로그
- 보물 상자 — 단독으로는 아이템이 아니다. 앞말이 잘린 것으로 보고 이어 붙인다

미지의 소울 조각·갱신권·하트 토큰은 아이템으로 센다.

## 범위 밖 (이번에 안 하는 것)

- **더블 루팅 전리품** — 결과창 스크롤 아래 "더블 루팅 전리품" 섹션은 OCR이
  못 읽는다("발견한 전리품" 헤더가 화면 밖으로 나가 수집 구간을 못 잡는다).
  이건 OCR을 손보는 대신 **패킷에서 읽어 딜미터기 세션에서 별도로 진행한다.**
  게임 서버가 포트 16000에 평문 TCP로 전리품을 보내는 것을 실측으로 확인했다.
  이 대시보드는 그 결과 로그가 준비되면 소스로 받는다.
- **같은 아이템이 여러 칸에 뜨는 경우** — 골드가 획득 경로별로 여러 칸에 갈려
  뜨는 것을 화면·인식 결과로 확인했다. OCR 로그에는 한 개로만 남고 수량도 한
  칸 것만 잡힌다. 영혼석은 한 칸에 뱃지로 뜨므로 이번 목적에는 영향이 없다.
  골드·장비의 정확한 집계는 위 패킷 경로로 넘어가면 함께 해소된다.
- **automator(앱) 수정** — 좌표 기반 칸 구분, 미기록 입장 방식 보완 등은 앱
  코드를 고쳐야 한다. 이번엔 앱을 건드리지 않고, 이미 쌓인 로그를 읽는 데
  집중한다. 앱 쪽 정확도 개선은 패킷 경로가 대체한다.
- **메뉴바 앱에서 바로 열기** — Swift 수정과 재빌드가 필요하다. 서버는 그대로
  두고 나중에 얹을 수 있다.
- **폰에서 보기** — 맥에서만 본다. 외부 공개는 하지 않는다.
- **수량 뱃지를 두 줄로 갈라 읽는 문제** — 경험치가 판당 수백만으로 뜨는 등
  큰 수의 신뢰도가 낮다. 아이템별 신뢰도 표시까지는 이번에 안 한다.

## 범위 밖 입력을 만나면

**처리한다. 단 조용히 처리하지 않는다.**

교정 사전에 없는 문자열을 만나면 버리지 않고 "해석 못 한 문자열"로 세어
화면 상단 배지에 건수를 띄운다. 배지를 누르면 원문 목록이 나온다. 목록을
보고 교정 사전에 한 줄 추가하면 다음 새로고침부터 집계에 들어간다.

이렇게 정한 이유는 조용한 누락이 이 도구의 유일한 실패 방식이기 때문이다.
확률을 보는 게 목적이라 분자가 새면 판단이 틀어지는데, 버려진 문자열은 화면
어디에도 흔적이 남지 않는다.

같은 원칙이 세 군데 더 적용된다.

- 로그 파일을 못 읽으면 0판이 아니라 오류로 표시한다
- 입장 방식이 7~14칸이라 못 가르면 어느 쪽에도 섞지 않고 판정 불가로 센다
- 표본이 적은 칸은 숫자 대신 표본 수를 보여준다

## 테스트

**이음새는 집계 함수 하나다.** 로그 레코드를 넣으면 던전 × 입장 방식 ×
아이템 표가 나오는 지점. 교정 사전 적용, 붙은 문자열 분리, 입장 방식 판정,
시간당 환산이 전부 이 안에서 끝난다. 웹 화면은 결과를 그리기만 하므로
따로 테스트하지 않는다.

done 기준:

- 붙어버린 문자열이 각 아이템으로 갈려 집계된다
- 같은 던전의 다른 표기가 한 줄로 합쳐진다
- 5분 넘는 간격이 판당 소요에서 빠진다
- 입장 방식 판정이 세 갈래로 나뉘고 판정 불가가 어느 쪽에도 안 섞인다
- 사전에 없는 문자열이 미인식으로 세어져 결과에 함께 나온다
- 수량 뱃지가 없는 아이템이 1개로 세어진다
- 아이템을 고르면 던전 × 입장 방식별 시간당 획득 개수가 순위로 나온다

기존 분석 스크립트에 이미 검증된 규칙(던전 이름 정규화, 오독 교정,
자리 비움 제외 기준, 입장 방식별 집계)이 있다. 다시 만들지 말고 그것을 쓴다.

## 미해결

- 교정 사전을 어떤 형식의 파일로 둘지 정하지 않았다. 구현할 때 정한다.
- 패킷 전리품 로그가 언제 준비될지 미정이다. 그 전까지 대시보드는 OCR 로그로
  돌고, 더블 루팅 판은 집계에서 빠진 채로 둔다. 로그 스키마를 미리 맞춰
  두는 것 외에 이번에 패킷 쪽을 기다리지 않는다.
