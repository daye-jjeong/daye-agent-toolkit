# 재료 시세 차트 — 그때 얼마였는지 읽히게

> 상태: 유효
> 대체: docs/specs/2026-08-15-mabi-equipment-cost.md 의 "재료 단가표" 결정(스파크라인 부분)과 "큰 시세 차트" 범위 밖 항목

## 문제

재고 입력칸 옆에 재료별 14일 스파크라인이 붙어 있는데 **그때 얼마였는지 읽을 수 없다.** 72×18픽셀에 종가 14개를 욱여넣어 축도 눈금도 없다. 오르는 중인지만 겨우 보이고, "2주 전에는 얼마였나"에 답하지 못한다.

이게 중요한 이유는 재료값이 하루에도 크게 흔들리기 때문이다. 망령의 영혼석은 하루 안에 69~108로 움직였고 8월 12일을 기점으로 60원대에서 110원대로 올라섰다. 지금 화면의 단가 하나만 보고 사면 그게 평소보다 두 배인지 알 수 없다.

"싼 편 / 비싼 편" 판정이 붙어 있긴 하나 근거가 그림에 없다. 판정을 믿을지 말지를 사용자가 직접 확인할 방법이 필요하다.

## 해결

작은 자리에서는 **현재가와 2주 범위를 숫자로** 읽고, 모양이 궁금하면 **재료를 눌러 30일 차트를 펼친다.**

작은 줄은 선을 키우고 양 끝에 범위 값을 붙인다 — 모양과 절대값을 같이 준다. 큰 차트는 그날의 고가~저가를 옅은 띠로 깔고 종가를 선으로 그린다. 최저·최고였던 날짜에 라벨이 붙고, 현재가가 수평선으로 지나가 지금이 그 사이 어디인지 한눈에 보인다.

## 확정된 결정

| 결정 | 선택 | 왜 |
|---|---|---|
| 작은 줄의 모양 | 스파크라인을 키우고 **양 끝에 2주 최저·최고 값**을 붙인다 | 숫자만 두면(안 A) 모양이 사라져 큰 차트를 열기 전엔 오르는 중인지 모른다. 게이지(안 C)는 위치만 남고 형태가 사라진다. 셋을 실제로 그려 비교한 뒤 고른 것 |
| 작은 줄의 폭 | 입력칸 그리드를 3열에서 2열로 (넓은 화면은 3열 유지) | 선과 범위 값을 같이 두려면 칸당 300픽셀 남짓이 필요하다. 지금은 232픽셀이다 |
| 큰 차트를 여는 방법 | 재료 **이름**과 **스파크라인**을 누른다 | 그 줄에 수량 입력칸이 있어서, 줄 전체를 누르게 하면 입력하려다 차트가 열린다 |
| 큰 차트가 나오는 자리 | 그 재료 줄 **바로 아래**에 펼친다 | 표 행을 눌러 상세를 여는 동작이 이 페이지에 이미 있다. 별도 화면으로 보내면 재고를 넣던 맥락이 끊긴다 |
| 큰 차트의 형태 | **범위 띠** — 고가~저가를 옅은 띠로, 종가를 선으로 | 정통 캔들은 몸통 색(상승/하락)이 매수·매도 압력을 뜻하는데, 우리 값은 "그날 거래소 최저가"의 OHLC라 그 직관이 틀린다. 답해야 할 건 "그때 얼마였고 얼마나 흔들렸나"이고 띠가 그걸 그대로 그린다 |
| 큰 차트의 기간 | 30일 | 14일은 8월 12일 급등만 보이고 그전 수준을 모른다. 3개월 전체는 하루 폭이 눌려 최근 움직임이 안 보인다 |
| 큰 차트에 짚어줄 것 | 최저·최고였던 **날짜와 값** + 현재가 **수평선** | 셋 다 "지금 사도 되나"라는 한 질문에 답한다. 축만 두면 최저점을 눈으로 찾아야 한다 |
| 계산과 렌더의 경계 | 30일 자르기·최저/최고 지점·좌표 변환은 `trend.py` 순수 함수, SVG 문자열만 서버 렌더 | 기존 구조를 그대로 따른다. 좌표가 순수 함수면 "8월 8일이 최저였다"를 SVG 파싱 없이 검증할 수 있다 |
| 시세 이력 적재 범위 | 화면에 쓰는 **94종만** (재료 18 + 잔영·해연 76) | 원본이 1,199종을 통째로 주는데 92%가 가구·요리·데코다. 전부 쌓았더니 닷새 만에 329MB, 하루 71MB씩 늘었고 조회가 4.34초가 됐다. 지우고 필터를 건 뒤 24MB·0.017초 |
| 이력을 계속 쌓는 이유 | 원본 API가 언제 바뀔지 모른다 | 캔들이 있으니 우리 이력이 필요 없어 보이지만, 비공식 API라 응답이 바뀌거나 끊길 수 있다. 그때 우리 기록이 유일한 과거가 된다 |
| 캔들 신선도 표시 | 캔들이 하루 이상 낡으면 차트에 **기준일**을 적는다 | 일봉 수집은 곁다리라 실패해도 상단 노란 띠를 띄우지 않는다. 대신 차트를 보는 사람이 "언제까지 데이터인지"를 알아야 한다 |

## 범위 밖 (이번에 안 하는 것)

- **주봉·월봉 전환** — 원본이 주긴 준다(주봉 8건·월봉 3건). 30일 일봉이 자리 잡은 뒤 필요하면 붙인다
- **해연·잔영 완제품 76종의 차트** — 재료 18종만. 완제품은 표에서 값을 바로 비교하므로 추세의 값어치가 재료보다 작다
- **가격 알림** — "망령이 70 아래로 오면 알려줘". 알림 경로(메일·푸시)가 없고 계정도 없다
- **차트 위 드래그 확대** — 기간 고정 30일. 상호작용을 붙이기 시작하면 JS가 커진다
- **이력 중복 제거** — "직전과 값이 같으면 건너뛰기". 94종 필터만으로 하루 71MB가 9MB가 되어 급하지 않다
- **정통 캔들(몸통+심지)** — 위 "큰 차트의 형태" 참조. 데이터 성격이 맞지 않는다

## 범위 밖 입력을 만나면

전부 **처리하되 표시한다.** 숨기거나 0으로 메우지 않는다.

| 상황 | 처리 |
|---|---|
| 캔들이 아예 없는 재료 | 차트를 그리지 않고 "시세 이력 없음"이라고 적는다. 빈 차트를 그리면 데이터가 있는데 값이 0인 줄 안다 |
| 캔들이 한두 건뿐 | 위와 같다. 선을 그으려면 점이 둘은 있어야 하고, 그 정도로는 추세라 부를 수 없다 |
| 현재가가 30일 범위를 벗어남 | **차트 세로 범위를 현재가까지 넓힌다.** 급등해서 삐져나간 것 자체가 지금 가장 중요한 정보다. 잘라내면 "범위 안에 있다"는 거짓 인상을 준다 |
| 원본이 응답 형태를 바꿈 (`low`/`high` 필드가 사라지거나 이름이 바뀜) | 없는 필드는 건너뛰고 남은 값으로 그린다. 그릴 게 없으면 "시세 이력 없음"과 같이 처리한다 |
| 일봉 수집이 실패해 캔들이 하루 이상 낡음 | 차트에 기준일을 적는다(`8/17 기준`). 상단 노란 띠는 띄우지 않는다 — 곁다리 실패로 전체를 경고 상태로 만들지 않는다 |
| 값이 14일 내내 같은 재료 | "고정"이라고만 말한다. 백분위 판정을 씌우면 "비싼 편"이 되는데 거짓말이다 (특급 목재가 그렇다) |

## 테스트

이음새는 **`trend.py`의 순수 함수**다. 새로 뚫지 않고 기존 파일을 확장한다.

캔들 목록과 현재가를 받아 차트에 필요한 값을 돌려준다 — 30일로 자른 결과, 최저·최고였던 날짜와 값, 세로 범위(현재가가 벗어나면 넓힌 값), 각 점의 좌표. SVG 문자열 생성만 서버 렌더에 둔다.

픽스처는 망령의 영혼석 실측 캔들을 쓴다. 8월 12일 급등이 들어 있어 "범위가 넓은데 현재가가 그 위"라는 경우를 그대로 재현한다.

done 기준:

1. 30일 차트에서 최저·최고 지점의 **날짜와 값**이 실측과 일치한다
2. 현재가가 30일 범위 위로 벗어나면 세로 범위가 현재가까지 넓어진다
3. "범위 밖 입력을 만나면" 표의 여섯 행이 각각 테스트로 존재하고, 각 경우에 렌더가 죽지 않고 표시 상태가 나온다
4. 작은 줄에 2주 최저·최고 값이 숫자로 나온다
5. 재료 이름과 스파크라인에 펼침이 걸리고, 수량 입력칸에는 걸리지 않는다

## 미해결

- **차트 세로축 눈금을 몇 개 둘지** 정하지 않았다. 3개(최저·중간·최고)면 깔끔하지만 값이 좁게 붙은 재료에서는 눈금이 겹칠 수 있다. 구현하며 실측으로 정한다
- **2열 그리드가 좁은 화면에서 어떻게 접힐지** 확인하지 못했다. 지금은 `auto-fill minmax`라 자동으로 줄지만, 칸이 넓어지면 모바일에서 1열이 될 것이다. 실제 폭을 재고 정한다
